## Rationale
P4451, "Early Adoption of an Always-Enforced Label": the
assertion-control-specifier `< terminating >` after `pre`, `post` or
`contract_assert` makes a contract assertion a terminating one, every
evaluation of which uses a terminating semantic.  `-fcontracts-p4451`
enables it; `-fcontracts-p3400`, and so `-fcontracts-p3850`, imply it, and
like the other per-paper options it enables `-fcontracts`.

**With P3400 on, nothing here applies.**  The specifier is then an ordinary
P3400 label resolved by label lookup, so P3400 subsumes P4451: a program
P4451 accepts means the same under both.  Without P3400 the parser accepts
only `< terminating >` (`isTerminatingSpecifier`), and `terminating` is not
looked up as an expression: the assertion gets a bit, `IsTerminating`, and
the allowed semantics of P3400's `labels::terminating` --
`TerminatingContractSemanticsMask`, enforce, quick_enforce and prove -- set
in `BuildContractStmt` before the semantic is resolved.  So a configured,
dynamically selected or constant-evaluation semantic is adjusted exactly as
for that label, through the unlabelled path that already reads the mask.
There is no label object, so the violation record is an unlabelled
assertion's and nothing in the ABI changes.  The bit survives template
instantiation (`TreeTransform`), serialization, `ASTImporter`, and takes
part in profiling, ODR hashing and redeclaration matching (both
declarations' assertions have the specifier or neither does).

**The two lookup checks run where the specifier is parsed.**
[basic.contract.control] requires a declaration of
`std::contracts::labels::terminating` to precede the specifier and
unqualified lookup of `terminating` from it to find nothing or only that
declaration.  `CheckTerminatingSpecifier` does both with ordinary lookup --
so "precedes" is visibility, including what an imported module exports --
when `ParseContractLabelAndRequiresClause` meets the specifier: for a
member function that is the late parse at class completion, with the
parameters re-entered, as for the predicate.  The entity is whatever
qualified lookup finds, the inline-namespace one under P4451 alone.  The
late-parse cache keeps the specifier only when it is valid, diagnosing any
other (`<other>` under P4451; `<terminating>` without it, pointed at the
option); an eagerly parsed one without P3400 is skipped rather than parsed
as an expression, so its names are not also reported as undeclared.

**The library follows the flags.**  `__cpp_contracts` and
`__cpp_lib_contracts` take the private date and `__clang_contracts_p4451`
is defined; under it without P3400 `<contracts>` and the std module declare
`std::contracts::labels::terminating` alone, of an internal type in an
inline namespace, so it is never P3400's `terminating`.  The
feature-test-macro generator gains a `raised` field for a macro an
unadopted extension raises under a compiler macro.

## Compile gap
Needs `4200-p3400-core` (the allowed mask, the label parse it sits beside,
the labels gate in `<contracts>`), `2400-p3595` (configuration and dynamic
selection, which read the mask) and `4900-p4405` (the prove semantic in the
mask); all precede it.

**What threads through shared code lands with that code's owner**, inert
until this commit: the `ContractStmt` bit and its accessors, serialization,
import, profiling and dumping (`1020`, `1120`), the parser's and Sema's
`IsTerminating` parameters and the late-parse cache's keep-or-diagnose
(`1040`, `1060`), the redeclaration comparison (`1060`), the option's
forwarding, sub-flag entry and implication (`1140`, `6900`, `2400`), the
`__cpp_contracts` arm (`1000`), and libc++'s `<version>` value, its
generator and the std module's export (`1160`).  Each reads
`ContractsP4451` or the bit, which nothing sets before this commit.
