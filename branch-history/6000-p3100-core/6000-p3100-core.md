## Rationale
P3100, "Undefined Behavior Is Not a Contract Violation... Yet": the
framework that turns a sanitizer check, or a compiler-emitted check where
no sanitizer is enabled, into a contract violation with a chosen evaluation
semantic.

Everything in `6030`-`6330` depends on this commit.  It carries four
things:

**The routing vocabulary**, in
`compiler-rt/lib/sanitizer_common/sanitizer_contract_routing.h`.  Its
header comment is the one thing to read before anything else in this band.
Four runtimes -- asan, ubsan, tsan and msan -- need the same wire enum, the
same populator struct and the same `extern "C"` entry point, and the entry
point is **unmangled**, so four private copies of its prototype would be
four chances to disagree with nothing to diagnose the disagreement.
libasan links libubsan, which would put two of them in one shared object.
Declaring the vocabulary once also means an upstream compiler-rt sync
touches one file we add rather than four it maintains.

**The wire is a weakly-defined byte**, and that is what makes the whole
scheme opt-in at link time: an absent symbol reads as zero,
`kContractRouteStock`, so a program built without routing behaves exactly
as it did before.

**`-fsanitize-semantic=<check>:<semantic>`**, using the same check taxonomy
as `-fsanitize=`, parsed and validated in the driver and re-rendered to
`-cc1` as resolved per-check semantics.  It has no `-fno-` form on purpose:
a check must never be silently skipped.  `-fsanitize-semantic-print` is the
undocumented testing seam that prints what the driver resolved.

**The implicit-assertion guards** in `CGExprScalar.cpp` and
`CGContracts.cpp`, for the case where P3100 is on and the corresponding
sanitizer is *not*.  `EmitImplicitIntOpGuard` and `emitImplicitGuardReaction`
are the shared reaction path; the per-check predicates that feed them are
factored so the sanitizer and the contract guard share one definition --
`EmitFloatCastInRangePredicate` is the clearest example, used by both.

The individual checks are one commit each from `6100` on, because the list
grows and shrinks as the work continues and a reviewer should be able to
take the framework without taking any particular check.

## Compile gap
Needs `1100-p2900-base-codegen` for the emission path, `2200-libcontracts`
for the handler entry point, and `2400-p3595` for semantic resolution.  All
precede it.

`ASTContext.h`'s declaration hunk is **cut**, and this commit takes piece
`:1` -- the raw-`SourceLocation` overload of `BuildViolationObject`, needed
because an implicit assertion has no `ContractStmt` to describe it.  Piece
`:0` is the base overload in `1020-p2900-base-ast`; the two sit in one hunk
with no blank line between them.

**Inward, every commit from `6030` to `6330` reaches into this one** -- the
runtimes implement the populator this header declares, and the checks call
the guard reaction it defines.  None is stubbed here.

**Behaviour trap:** with this framework in and no runtime commit,
`-fsanitize-semantic=` is accepted, the wire byte is emitted, and the
sanitizer that reads it does not exist yet -- so the check reports in its
stock form and the configured semantic is silently not applied.  The weak
symbol that makes the scheme safe is also what makes this failure quiet.
