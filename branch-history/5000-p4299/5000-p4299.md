## Rationale
P4299, "Contracts for C": `_Pre`, `_Post` and `_ContractAssert` in the C
front end.

The keywords are `KEYWORD(..., KEYCONTRACTSP4299)` entries in `TokenKinds.def`,
so they are keywords only under `-fcontracts-p4299`, in C or C++ (the
`KEYCONTRACTSP4299` flag itself is declared beside `KEYCONTRACTSP3400`, by
adjacency in `4200-p3400-core`), and
the rest of the compiler-side work is one block in `ParseFunctionDeclarator`
that defers a C contract's tokens the same way C++ defers a member
function's.

**The interesting part of that block is the case it guards against.**  A
contract written on a *parameter's* own function declarator has nothing to
attach to: the parameter is not a function being defined, so the replay in
`ParseFunctionDefinition` never runs for it and the cached tokens would
reach `Declarator::clear()` unconsumed and trip its assertion.  It is
diagnosed and dropped instead.  The comment records the cross-compiler
position: GCC accepts and ignores the same construct, so ignoring it
matches -- the diagnostic is the only difference worth having.

C is **callee-side only** -- there is no caller-side checking in the C
front end on either compiler -- and P4299 is deliberately excluded from the
set of flags that imply `-fcontracts`, since it enables the C facility
rather than the C++ one.

The library side is `<stdcontracts.h>` and the `stdc_*` entry points, both
of which ride with `2200-libcontracts` because they are part of the C
runtime rather than of this front-end change.

## Compile gap
Needs `1040-p2900-base-parse` for the late-parsing machinery the C path
reuses, `1100-p2900-base-codegen` for emission, and `2200-libcontracts` for
the `stdc_*` entry points.  All precede it.

None outward.

**Behaviour trap:** with `-fcontracts-p4299` off, `_Pre` is not a keyword
and a C contract is a syntax error, which is loud.  The quiet failure is
the parameter-declarator case above -- before the guard it was an
assertion failure in a debug build and undefined behaviour in a release
one, which is the worst combination for something a user can write by
accident.
