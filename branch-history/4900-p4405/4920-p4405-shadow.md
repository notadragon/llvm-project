## Rationale
The second proving strategy for the P4405 `prove` and `diagnose`
evaluation semantics, proof shadows, and the assumption
`-fcontracts-prove-assume` makes of what they prove soundly.  An
evaluation folding does not settle is proven when the optimizers can show,
in a copy of its function that is optimized but never emitted, that its
predicate cannot be false where it is evaluated.

`-fcontracts-prove-shadow` (implied by `-fcontracts-p4405`, so by the
umbrella `-fcontracts-p3850`; `-fno-contracts-prove-shadow` turns it off on
either side of it; C and C++) selects the strategy,
`ContractProveShadowStrategy` in `CodeGen/ContractProveShadow.cpp`, the
second registry entry.  It cannot answer where code generation describes
the evaluation, so it uses the proving interface's deferral (`4900-p4405`):
when the module is optimized (`-O1` and up, even with the LLVM passes
disabled, as `-save-temps` does for the step that writes the bitcode; no
front-end profile instrumentation or use, coverage mapping or
optimization-record file; not OpenMP, CUDA, OpenCL, SYCL device, HLSL or
the incremental compiler) and the function can have a shadow (not
`optnone`, naked, multiversioned or a coroutine), an evaluation becomes an
obligation with an id, recorded in the module's
`clang.contract.obligations` metadata (locations, flags, decision), and
the strategy's `PlaceDeferred` emits its part wherever the evaluation is
emitted.  A caller-side precondition is deferred only when every argument
its predicate uses can be evaluated again -- no side effects, a scalar or
reference parameter, `this` from the implicit object argument -- and not
for a constructor, destructor or lambda.  While shadows are made it also
takes over every diagnostic decided at once (`TakeDiagnostic`), so that the
back end issues all of them in order; one met while a shadow or a
predicate is emitted is dropped (a call inside a predicate is not
evaluated by the program, `p4405-shadow-predicate-call.cpp`).

From `Release` (`emitContractProofShadows`), each function holding an
obligation is emitted a second time through `GenerateCode`, into an
internal `<name>.contract.proof` function carrying the attribute
`clang.contract.proof`, without debug information and with diagnostics
suppressed; whatever that makes code generation emit is emitted too.
Its indirect return slot is marked `nonnull` (unless null pointers are
valid): it is the result object, which exists.
There an obligation is `if (!pred) __clang_contract_unproven(id)`, a
noreturn call, so a false predicate ends its path and cannot make later
code unreachable (P4021R2 Example 2 stays ill-formed), and an earlier
evaluation is an assumption, `if (!pred) unreachable`
(`emitContractShadowAssumption`, hooked at the top of
`emitCheckForSemantic`): `assume` (guaranteed), `ignore`, `observe` and
`noexcept_observe` (not guaranteed, which makes every proof in the shadow
conditional); `ignore` and `assume` only for a predicate without side
effects of its own, since they do not evaluate it -- a call is not one
(D4405R0, "Previous Assertions and Undefined Behavior"): such a predicate
is emitted with its calls tagged `cs::PremiseTag`, and the back end judges
them as an obligation's.  `enforce`, `noexcept_enforce` and
`quick_enforce` need nothing: their violation paths do not return.  The
calls and stores a predicate emits are tagged with `clang.contract.pred`
metadata (the `InsertHelper` hook).

`CodeGen/ContractShadowDecide.cpp` decides, from `BackendUtil`'s
`RunOptimizationPipeline` before the pipeline runs.  The shadows and the
functions they use are cloned into a proof module of their own (other
variables as external declarations, so that nothing is assumed of their
values, constant ones keeping their initializers) and optimized with the
default pipeline of the `-O` level, its diagnostics silenced.  An
obligation is unproven if a marker call for it survives, "always false" if
that call is reached from its shadow's entry through straight-line code
outside a loop, and proven otherwise: conditional if its shadow holds an
assumption that is not guaranteed, an unproven obligation, or a predicate
with an effect of its own (a store other than to a local, an indirect call,
or a call of a function that, once optimized, is not known to only read
memory, return and not throw -- by attributes, or for an inline function
by its body -- or, out of line, of a replaceable one holding an unsettled
evaluation, whose other copies may evaluate it with observe; DECISIONS.md
E214), or an assumption the real code does not evaluate whose predicate
calls such a function or, even inlined, such a replaceable one, sound
otherwise.  Undefined behaviour makes a path
unreachable and is a guaranteed premise.  Copies of an obligation
(constructor variants, unrolling) are one obligation, the worst copy
deciding.  The shadows and everything only they used are then deleted from
the real module, so it is optimized and emitted exactly as without them
(`p4405-shadow-same-code.cpp`; inlining included,
`p4405-shadow-real-inlining.cpp`; a function called once from real code
and once from a predicate, inlining across many callers, constant and
argument propagation, a cold caller, identical functions, a comdat
function, label numbering, and a variable stored to or a function's
address taken only by a predicate, `p4405-shadow-same-code-*.cpp`; under
`-fmerge-functions`, which the proof module is optimized without, so that
it neither replaces a function the decision holds nor changes a remark,
`p4405-shadow-merge-functions*.cpp`), under `-flto` too, where nothing reaches
the bitcode; every recorded evaluation not proven is diagnosed, with a
`-Rcontract-proof` remark giving each shadow result (the remark and its
group are defined with the other P4405 diagnostics, in `2400-p3595`'s
lines).  An error that stops compilation before the back end diagnoses the
deferred evaluations as unproven (`ModuleBuilder`'s hook).  Each obligation
records the template instantiation context of the function it is emitted
in (`4900-p4405`'s `getContractDiagnosticContext`; `DiagContext`, the
eighth field of its record), and the back end, given the `ASTContext` by
`BackendUtil` (none for IR input), follows its diagnostic with that
context's notes -- rendered when the obligation was recorded, so they
survive `-clear-ast-before-backend`, which the driver passes -- and the
diagnostics are the same with and without shadows
(`p4405-shadow-template-context*.cpp`).

An evaluation folding finds always false is deferred all the same when a
shadow can take it (notadragon_wg21 DECISIONS.md E195: an evaluation never
reached is proven -- reaching no point is a proof): `proveContract` keeps
asking after folding's "always false" and, if a strategy defers, sets the
query's `FoldedFalse`, recorded as the obligation's `FoldedFalse` flag.  The
back end then decides only whether it is reached: proven if its marker is
removed as unreachable (soundly unless the shadow is conditional), "always
false" wherever it survives or nothing decides it.  A nested evaluation
keeps folding's answer.  A surviving one is a premise for the rest of its
path, as any unproven obligation (E196 item 1).  Tests:
`p4405-unreachable-O0.cpp`, `-O1.cpp`, `-O2.cpp` (claimed by
`4900-p4405`'s pattern), `p4405-premise-unproven*.cpp`, and the watch test
of CLANG-910 (`OpenBugs/p4405-shadow-exception-inlined.cpp`) with the
control `p4405-shadow-exception-inlined.cpp`.

`-fcontracts-prove-assume`: a deferred evaluation leaves in the real
function `if (__clang_contract_proven(id)) llvm.assume(pred)`, which the
back end keeps for a sound proof -- marking the predicate's calls as only
reading memory, returning and not throwing, as the shadow found them, so
that nothing of the predicate is ever evaluated -- and deletes otherwise,
before the real module is optimized (rejoining the code around a deleted
one), so an unproven evaluation leaves exactly `ignore`'s code.  A pass at the end of the pipeline
(`registerContractAssumeCleanup`) removes the assumptions and any function
only they used.  Not under an instrumenting sanitizer, nor when the
module itself is not optimized (`-save-temps`, `p4405-shadow-save-temps.cpp`).

A proof relies only on premises this translation unit decides.  A
terminating check (`enforce`, `noexcept_enforce`, `quick_enforce`) is a
premise only where this TU's copy of its function runs, unless the
assertion's allowed set (its label's, which every TU sees) holds none of
`ignore`, `observe`, `noexcept_observe`, `diagnose` and `prove`; code
generation lists the functions holding such checks in
`clang.contract.premises` (the shadow hook in `emitCheckForSemantic`).
Cloning keeps every linkage, so LLVM's refusal to reason from an inexact
definition (`linkonce_odr`, `weak_odr`, `available_externally`, `weak`)
holds in the proof module as in the real one, and the proof module's
inliner remarks record what was inlined into what.  A shadow is conditional
if it, or a function with an exact definition it calls out of line,
transitively, calls out of line a replaceable function whose code holds
such a premise or inlined one.  A shadow whose code relies on an inlined
copy of one stays sound only if the real code inlines the same function:
for a proof whose assumption it keeps, the back end makes each such call
`always_inline` in the real module (after checking that the inliners would
honour it; a pass at the end of the pipeline warns should one survive),
and otherwise the proof is conditional and the real code unchanged
(`-mllvm -contract-proof-force-inline=false` gives that for any proof).
The `p4405-premise-*` tests are the matrix over linkage, inlining,
position, semantic, allowed set, `-O0`, copies and calls through other
functions, with run tests linking two TUs that give one inline function
different semantics; `Runnable/enforce-ipa-replaceable.cpp` shows that
ordinary code (no P4405) exports nothing from an inline function's check.

Rule 1 covers more than premises: a shadow may rely on what an inlined
replaceable function does not do as well as on what its checks guarantee,
and another TU's copy may differ in either -- an `ignore`d assertion here,
an `observe`d one whose handler stores and returns there.  So code
generation also lists, in `clang.contract.refinable`, every function
holding an unsettled evaluation (`noteContractRefinableBody`, from
`GenerateCode`; `1100-p2900-base-codegen`'s `CurFnHoldsUnsettledContract`,
settled by a label as in `4230-p3400-facet-allowed-semantics`), and rule 1
forces (or makes conditional) every inlining of a replaceable function
holding, or having inlined, one; the replaceable-callee check stays
premise-based, as gnu_gcc's.  A label settling the premise but not the
refinable body (`{enforce, quick_enforce, noexcept_enforce, assume}`: one
copy's handler may throw where another traps) therefore no longer spares
the forcing (`p4405-premise-allowed.cpp`'s `settled` and
`settled_nothrow`).  `p4405-premise-shadow-only-effects.cpp` and
`Runnable/p4405-premise-multi-tu-effects.cpp` show the case;
`p4405-premise-late-summary-caller.cpp` mirrors gnu_gcc's test of a
function whose only unsettled evaluation is a caller-side one.

The machinery also carries `4940-p4405-override`'s override shadows.  A
shadow may be an override pair's (`<name>.contract.override.<n>`, attribute
`clang.contract.override`), where an ordinary obligation is a premise,
listed in the shadow's `clang.contract.relied` metadata; the back end
decides the override shadows after the proof shadows, and an override
shadow's proofs are conditional unless every obligation it relies on is
proven soundly.  An override pair's assertions of `B::f` are given
`D::f`'s parameters, or the copies taken at entry, and the `B` subobject
(`OverrideBinding`, `ContractOverrideSnapshot`); a pair's obligation is
recorded with `B::f`'s name (the record's ninth field) and is never an
assumption in the real code; and `canMakeContractShadows` is the
conditions both kinds of shadow share.  The `-Rcontract-proof` remark says
"override shadow" for an override shadow's result.

The evaluations nested in an obligation (D4405; notadragon_wg21
DECISIONS.md E169: the analysis evaluations of the preconditions of the
calls in its predicate, recursively) are placed in its shadow as its
predicate is emitted, at each call (`emitContractShadowNested`, from
`DiagnoseCallerSideProvingContracts`): folded first, in the call's frame;
recorded with the result when folding decides one with nothing nested in
it, or one that cannot be deferred (a constructor call; arguments that
cannot be given again), with those nested in it decided by folding too;
otherwise a nested obligation (the record's tenth field, its parent),
whose region, ahead of the call, is a side branch behind an opaque guard
that never rejoins the path, `if (__clang_contract_nested(id)) { if (!pred)
__clang_contract_unproven(id); llvm.trap(); }`: decided where the call is
evaluated, before anything the callee does can make the path unreachable,
and no premise for what follows, so its failure does not make the
shadow's other proofs conditional.  The back end combines each
obligation's result with those nested in it
(`combineNestedContractResults`) for the diagnostics, the notes and the
assumptions; the `-Rcontract-proof` remark shows both and marks a nested
obligation's.  In a real function's assumption nothing is placed at the
calls of the predicate, which the program never evaluates, so the
evaluation at the same call in a check is not taken for one made there;
and `foldPlaceholders` rejoins the code around a dropped region only if
that region was not inside another one deleted.  An override pair's
obligation nests too (E169 (8)): in its override shadow, or without one in
D::f's proof shadow, its nested obligations inherit the pair (named for it
in their diagnostics, "override shadow" in the remark).  Each obligation
records its report-once group (the record's eleventh field): the place --
assertion and call -- of the outermost evaluation it is nested in, or of
the check that evaluation at a call is made in (`4900-p4405`'s
`getContractCheckPlace`); the back end and `reportContractProofsNow`
issue a diagnostic a nested `diagnose` obligation and the evaluation at
the same call make once per group (E169 (9), (11)).  An evaluation at a
call in code not emitted (`InContractDeadCode`, set by
`4930-p4405-analysis`'s `analyzeContractDeadCalls`) is never deferred.

D4405's callee premise copies (notadragon_wg21 DECISIONS.md E199 (b)) ride
with the shadows: `-fcontracts-prove-callee-premises` (implied by
`-fcontracts-p4405`, `-fno-` on either side of it; C and C++) is a strategy
of its own, in `CodeGen/ContractProvePremises.cpp`, but it exists only
inside the shadow pipeline -- no shadow, no copy -- and its hooks are in
the files above.  A shadow takes the `observe`, `noexcept_observe` and
`ignore` evaluations it emits itself as premises, while the functions it
calls and inlines are the real ones, which hold nothing for them (CLANG-911,
the bindels example's `else` branch).  So code generation notes each real
function whose code holds such an evaluation (`noteContractPremiseCopy`,
from `emitContractShadowAssumption`'s real-function path) and, once some
shadow is made, emits it once more as `<name>.contract.premise` (attribute
`clang.contract.premise`): internal, never emitted, its code the real code
but for those evaluations, assumed as a shadow assumes them, and no
obligation (`ContractShadowFunction::PremiseCopy`; `placeShadowObligation`
places nothing there).  The back end decides the shadows as before, with
the real functions; then the shadows holding an obligation left unproven or
always false that use a function with a copy (directly or through what they
use) are decided again in a second proof module where every use of such a
function is a use of its copy
(`decidePremiseRound`); an obligation proven there is proven conditionally,
never an assumption.  The copies are deleted with the shadows.  The first
round is unchanged, so the output is the same with the option on or off,
`-fcontracts-prove-assume` included (`p4405-shadow-callee-premises-same-code.cpp`).
Tests: `p4405-shadow-callee-premises*.cpp` (the reduced shapes, under `observe`,
`ignore` and `noexcept_observe`, a callee reached through a function without
contract assertions, the bindels example, not assumed, `-O0`, the same
code); the `p4405-premise-*`, `p4405-nested-checked.cpp`,
`p4405-nested-caller-side.cpp` and `p4405-override-dtor*.cpp` tests, which
pin what a callee's own code leaves, pass
`-fno-contracts-prove-callee-premises` (`p4405-premise-semantic.cpp` and its
C twin check both forms).

D4405's proof optimization level (notadragon_wg21 DECISIONS.md E162-E168,
E205, E207), `-fcontracts-prove-optimize=<0|1|2|3|follow>` (driver and
`-cc1`, C and C++, no `-fno-` form, the last one winning; a bad value is an
error, in the driver whether or not the option has an effect), says how
hard the proofs are tried, independently of the code-generation level.  The
front end resolves it into `LangOpts.ContractsProveOptimize`, 0-3: by
default the `-O` level but at least 2 (`-O3`, `-O4`, `-Ofast` give 3), with
`follow` the `-O` level, where `-Os`, `-Oz` and `-Og` count as 2.  Each
strategy `-fcontracts-p4405` implies is on from a level -- folding from 0,
the proof shadow and assume from 1, the override shadows and the callee
premise copies (which need the shadow) from 2 -- and one given explicitly,
in either form, wins; the round trip records the resolved level and each
strategy not at its level's default.  BackendUtil optimizes the proof
module (both rounds, override shadows included, X13's MergeFunctions-off
kept) at that level (a strategy given at level 0 runs at level 0, where
the proof module is optimized as at `-O0`; DECISIONS.md E208 (a)), with
tuning options for it: unrolling and interleaving from 2 unless
`-f[no-]unroll-loops` was given (`CodeGenOptions::UnrollLoopsGiven`), the
vectorizers from 2 unless their setting differs from the `-O` level's
default (the driver resolves them, so that is all `-cc1` can tell).  What
the `-O` level alone puts in the module is replaced in the proof module
(`normalizeProofModule`, after cloning): `-O1`'s
`llvm.loop.unroll.disable`, which code generation lists when the proof level
unrolls (`LoopAttributes::UnrollDisableImplied`, `CGLoopInfo`;
`clang.contract.unroll.implied`), and `-Os`'s and `-Oz`'s `optsize` and
`minsize`, dropped from every proof-module function and call but where a
function's own `cold` or `minsize` asks for it (`clang.contract.size`,
listed when a shadow is made); shadows and premise copies take their real
function's.  Both lists are erased from the real module, which is
untouched.

`-O0` modules prove at the proof level too (stage 2; 2 by default,
`follow` giving 0): the shadow gate no longer asks for an optimized
module.  Where an `-O0` module proves at a level above 0
(`contractProofsAtO0`), code generation makes what the level needs and
`-O0` does not, for the proofs only: TBAA (`CodeGenTBAA`; not under
`-fno-strict-aliasing`, ThreadSanitizer or TypeSanitizer) and the
`!range`/`!noundef` of bool and enum loads (`CGExpr.cpp`), stripped from
the real code by the back end with `!llvm.errno.tbaa`; the bodies of
`available_externally` functions (`shouldEmitFunction` notes them,
`emitContractProofShadows` emits them once a shadow is made, without debug
information, and moves each into `<name>.contract.external`, restoring
the declaration's attributes), which the proof module uses in place of
the declarations and the real module deletes with the shadows; and a list
(`clang.contract.o0`) of what the proof level does to each function's
attributes that `-O0` does not -- no `optnone`, no `noinline` but what the
declaration or the inlining flags give (`CodeGenOptions::
ContractProofInlining`, which records `-fno-inline`,
`-fno-inline-functions` and `-finline-hint-functions` at `-O0` and round
trips them), `inlinehint`, `optsize` for a cold function -- applied in
the proof module to the functions, shadows and premise copies.  The
allocas made for a real function's assumption region are marked, and
deleted with the region when nothing else uses them; a kept region's
empty blocks are merged back and its allocas deleted when the assumption
is (`ContractAssumeCleanupPass`), so the real `-O0` code is the same with
and without the proofs, assumptions kept or not (but for a call a sound
proof relies on inlining, which the real code then inlines, and the IR's
value names).  Not done: `available_externally` vtables.  A premise copy
assumes nothing of a postcondition with captures (CLANG-913: it crashed,
the capture being emitted only where the postcondition is checked).
What the shadow phase emits leaves the real module alone: the speculative
(`available_externally`) vtables are emitted before the shadows, from the
inline virtual functions the real code emitted, and those only the
shadows ask for are not (CLANG-914: a predicate's qualified call let a
vtable be emitted and the real code be devirtualized through it); and the
phase runs without the module's debug information, at every level
(CLANG-915: with `-g` the types a predicate names and the vtables a
shadow loads were described).
Tests:
`p4405-prove-optimize-*.cpp` (the table with every explicit form and

and what the program's own attributes, pragmas and flags keep, and the
same-code shapes at a fixed level across `-O1`, `-O3`, `-Oz`; at `-O0`: the

`p4405-shadow-callee-premises-post-captures.cpp` (CLANG-913),
`p4405-shadow-debug-info*.cpp` (with `-g`, the object code the same with

inlined one by the inlining rule, conditional too).

## Compile gap
None.  The strategy uses only the proving interface (`4900-p4405`) and the
code generation and back-end hooks this commit adds.  As for the folding
strategy, the lines that make `-fcontracts-p4405` imply the flag
(`CompilerInvocation.cpp`, `2400-p3595`) name `OPT_fcontracts_prove_shadow`
and `OPT_fcontracts_prove_callee_premises`, which this commit declares;
that commit's gap covers them, and the `LangOptions.def` entries are
`1000-p2900-base-basic`'s.  So are `OPT_fcontracts_prove_optimize_EQ` and
`LangOpts.ContractsProveOptimize`, which `2400-p3595`'s lines resolve.

**Behaviour gap: the driver does not pass the flag on before
`6900-cross-paper-options`**, whose contracts block in `Clang.cpp` forwards
it; until then only a `-cc1` command line sees it.  The tests that use the
driver (the `-###` lines of `p4405-shadow-off.cpp` and
`p4405-shadow-explicit.cpp` and `p4405-prove-assume-off.cpp`, the
`Runnable/` tests) cannot pass before `6900`.  The
`p4405-prove-optimize-*.cpp` tests, which also exercise the analysis
semantic (`4930-p4405-analysis`), the override shadows
(`4940-p4405-override`) and the driver's option rule and forwarding
(`6900`), cannot pass before those.  The C mode's tests
(`clang/test/Contracts/C/c-p4405-shadow-*.c`) ride with `5000-p4299`.
