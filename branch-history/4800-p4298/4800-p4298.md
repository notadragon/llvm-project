## Rationale
P4298, "Nonthrowing Contract Evaluation Semantics": `noexcept_enforce` and
`noexcept_observe`, which behave as their plain counterparts except that
contract-violation handling never propagates an exception out.

The semantics themselves are already in the enumeration --
`1000-p2900-base-basic` defines every semantic, including these, because
the base enumeration is one thing and the gates on it are another.  What
this commit adds is the flag, the feature-test macro, and the library's
side of the facility.

The library piece worth reading is `is_nonthrowing`, and its comment says
what is unusual about it: it is a **free function** rather than a
`contract_violation` member, unlike `is_terminating` beside it, because it
classifies a bare `evaluation_semantic` value rather than a violation that
has already happened.  It is also placed unconditionally, not under the
P4298 guard -- the classification is a static property of the enumerators
and is usable whether or not the feature is on.

`handle_observed_contract_violation(nothrow_t, ...)` is the manual
reporting API's nonthrowing overload, and it picks `noexcept_observe` or
plain `observe` depending on whether `__cpp_contracts_nonthrowing_semantics`
is defined -- so the same call means the strongest thing available.

`2400-p3595`'s rule that a dynamic selection under a label allowing no
throwing semantic brings none in (DECISIONS.md E137 and E138) is tested
here, where the labels and these semantics exist:
`Runnable/p3595-dynamic-nothrow-label-*.cpp` (a throwing handler
terminates, for a selected observe or enforce, an invalid selection, the
weak default selector, and an out-of-set `compute_semantic` result, which
is an invalid selection; the `*-no-p4298.cpp` ones trap as quick_enforce
without calling the handler, also under a label not allowing
quick_enforce), `Runnable/p3595-dynamic-nothrow-capture*.cpp` (the same
for a postcondition with P3098 captures) and the controls
`Runnable/p3595-dynamic-throwing-label*.cpp`, gnu_gcc's tests of the same
names.

Constant evaluation needs nothing here: `1090-p2900-base-sema-constexpr`
already treats the noexcept variants as indistinguishable from their plain
counterparts, because during constant evaluation there is no throw or
terminate to distinguish.

## Compile gap
Needs `1000-p2900-base-basic` for the enumerators,
`1160-p2900-base-libcxx` for `<contracts>`, and `2200-libcontracts` for the
noexcept entry points the ABI already declares.  All precede it.

None outward.

**Behaviour trap, and this is the one that bit before:** if the umbrella
flag does not imply `-fcontracts-p4298`, `noexcept_enforce` and
`noexcept_observe` silently downgrade to `enforce` and `observe` -- a
throwing handler then propagates where it was required to terminate, with
no diagnostic anywhere.  The implication is performed by the driver block
in `6900-cross-paper-options`, so between this commit and that one the
downgrade is the actual behaviour.  `p3850-implies.cpp` in
`1140-p2900-base-driver` is what pins it once both are in.
