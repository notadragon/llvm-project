## Rationale
P3097, "Support for Contracts on Virtual Functions" -- **adopted into the
working draft at Brno**, so of everything in the 3000 band this is the one
closest to final wording.

P3097's model is two-source: a call through a base-class pointer checks the
*interface* contracts of the statically named function, and the override
that actually runs checks its own.  Neither inherits the other's.

**Clang implements that with a wrapper function, and that is the whole
commit.**  `getOrEmitVirtualContractWrapper` emits, per virtual method with
contracts, an internal `noinline` function named `<mangled>.__contract_wrapper`
that checks the interface contracts and then performs the vtable dispatch;
`EmitCXXMemberOrOperatorMemberCallExpr` redirects the call site to it
instead of dispatching directly.  The dispatch has to stay dynamic inside
the wrapper -- the override selected at run time is the one whose own
contracts run, which is the half of the two-source model the wrapper does
not itself check.

Two things worth a reviewer's attention:

**The wrapper is built like a thunk, deliberately.**  `CurFuncIsThunk`,
`buildThisParam`, `EmitInstanceFunctionProlog` -- it is the same
construction Clang already uses for covariant-return and virtual-base
adjustment thunks, because the problem is the same one: a synthesized
function with the callee's signature that forwards.  Reading it as a thunk
rather than as a new kind of function is the shortcut to understanding it.

**A wrapper is emitted only if a contract is actually active.**  The call
site resolves each interface contract's runtime semantic first, and falls
back to a plain virtual call when all of them are `ignore`.  That check is
not an optimization -- without it, configuring contracts off would still
route every virtual call through an extra `noinline` function.

**Clang's P3097 has no Sema component at all.**  Its only diagnostic is the
flag gate; the rule that a contract may not be added to a virtual function
is GCC's, inherited from GCC's base implementation, and Clang's base never
had it.  So where GCC's P3097 commit has to *lift* a prohibition, Clang's
only has to add the wrapper.  That asymmetry is real and is why the two
commits at this band number look so different.

**A caller of a wrapper holds this TU's evaluations.**  The wrapper is
internal and the call-site checks (a C-variadic function, a destructor)
are in the caller's own code, so another translation unit's copy of the
caller may evaluate the contracts differently, or not at all: the caller
is marked (`CurFnHoldsUnsettledContract`, `1100-p2900-base-codegen`'s
refinable-body rule) whatever the label.  For a noexcept virtual function
the nounwind this costs was right in every copy; the mark is kept because
P4405's proof shadows may not rely on an inlined copy of such a caller
either (`4920-p4405-shadow`).

**Outside the body, a noexcept function's contracts still terminate.**  A
throwing violation handler (or selector, or capture) in the evaluation of a
noexcept virtual function's interface contracts must terminate the program,
as it would in the function's body; the wrapper is set up like a thunk, so
`StartFunction` has no declaration to take the exception specification
from, and the call-site checks are in a caller that may itself throw.  So
the wrapper body and the call-site checks enter a terminate scope of their
own when the callee is noexcept (`interfaceContractsTerminateOnThrow`;
`Runnable/p3097-noexcept-caller-side-terminate.cpp`, calls made through a
volatile function pointer so the caller keeps its handler).  This is also
why a unit that leaves the interface contracts unchecked, and so finds a
caller of a noexcept virtual function nounwind, agrees with a unit that
checks them (DECISIONS.md E136 has no Clang form;
`6970-refinable-body-tests`).

## Compile gap
Needs `1100-p2900-base-codegen` for the contract-emission path the wrapper
body reuses and `2400-p3595` for `ensureRuntimeSemantic` to answer
anything but the default; both precede it.

None outward.  `4650-cross-feature-matrix` depends on this commit, but only
for tests.

**Behaviour trap:** with `-fcontracts-p3097` off, a contract on a virtual
function is diagnosed, so the failure mode is loud.  With the flag on but
this commit's CodeGen missing, it would not be: the contract would attach,
the call would dispatch normally, and the interface contract would never be
checked.  That is the shape the tests here are written against -- 44 files,
nearly all of them counting handler invocations through a base-class
pointer.
