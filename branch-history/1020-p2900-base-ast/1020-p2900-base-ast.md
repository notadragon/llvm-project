## Rationale
The AST representation of a contract, and the cost of introducing it.

Four new node kinds, registered in `StmtNodes.td` and `DeclNodes.td`:

* **`ContractStmt`** (`StmtCXX.h`) -- one `pre`, `post` or `contract_assert`.
  A `TrailingObjects` node over `Stmt *` and `const Attr *`, with six
  optional sub-statement slots (result name, condition, message, label,
  captures, requires-clause) counted by a `Has*` bit each.
* **`ContractSpecifierDecl`** (`DeclCXX.h`) -- the sequence of contracts
  attached to one function declaration, a `Decl` in its own right so that
  the same sequence can be shared, deferred and instantiated.
* **`ResultNameDecl`** -- the `r` in `post (r : ...)`, a `ValueDecl` so the
  predicate can name it like any other declaration.
* **`PostconditionCapture`** -- a `VarDecl` subclass, so that P3098's
  captures are variables everywhere that already handles variables.

**The single most invasive line is not in any of them.**  `FunctionDecl`
gains a `ContractSpecifierDecl *Contracts` member, and the constructor and
both `Create` overloads grow a parameter to carry it.  That re-signing, and
the callers it forces to change, is most of the 83 removed lines in this
commit -- there is no behaviour in them.

The rest is the tax a new node pays to be visible: `ASTNodeTraverser`,
`RecursiveASTVisitor`, `TextNodeDumper`, `StmtPrinter`, `DeclPrinter`,
`StmtProfile`, `ASTImporter`, `ASTMatchers`, libclang's cursor mapping, and
the static analyzer's `ExprEngine`.  Two of those come with tests, and
those tests are the ones worth reading: `ASTImporterTest` and
`ASTMatchersTraversalTest` are where a missing field shows up as a wrong
answer rather than as a crash.

Three things a reviewer should look at closely:

**The trailing-object layout is order-sensitive.**  The offset of the
attribute array is a function of the `Stmt *` count, so every `Has*` bit
that `numTrailingObjects()` consults must be set before the first
trailing-object access.  Get that order wrong for a contract carrying both
an attribute and a requires-clause and the attributes land one slot short
of where every later read looks for them -- silently, and a long way from
the constructor that caused it.  The comment in the constructor says so,
and the ordering it describes is load-bearing.

**`ContractStmt` carries storage for papers that have not landed yet** --
the cached runtime/constant-evaluation/caller semantics, and P3595's
`DynName_`, `DynLinkage_`, `DynTable_` for link- and run-time semantic
selection.  This is the same shape as `1000-p2900-base-basic`'s semantic
masks: the slot is in the base node because that is where the node is
defined, and the code that fills it is in `2400-p3595`.  Until then the
accessors answer "not dynamic" and nothing reads them.

**`VarDecl` grows a `RegisteredForDestruction` bit and
`recheckForConstantInitialization` grows an `EnableContracts` parameter.**
Those are the constant-initialization interaction, not bookkeeping: a
contract in a constant initializer can change whether the initialization
is constant at all, and the recheck has to be able to ask the question both
ways.

`ASTContext` gains the contract-violation record type and the descriptor
table the runtime is handed -- `getBuiltinContractViolationRecordDecl`,
`BuildViolationObject`, and the lazily-built descriptor `RecordDecl`s
beneath them.

## Compile gap
Depends on `1000-p2900-base-basic` for `ContractKind`,
`ContractAssertionKind` and the semantic enumerations; that commit
precedes this one, so nothing is owed backwards.

`ASTContext.h`'s declaration hunk is **cut**, and this commit takes piece
`:0`.  Piece `:1` is P3100's raw-`SourceLocation` overload of
`BuildViolationObject`, claimed by `6000-p3100-core`; the two overloads sit
in one hunk with no blank line between them and nothing else could
separate them.  Nothing here calls the P3100 overload, so no stub is owed
-- but a reader diffing this file against the final text will find it short
by one declaration, and that is why.

**Behaviour trap:** every node introduced here is unreachable.  Nothing
constructs a `ContractStmt` until `1040-p2900-base-parse`, nothing attaches
a `ContractSpecifierDecl` until `1060-p2900-base-sema-core`, and nothing
emits code for either until `1100-p2900-base-codegen`.  A build stopping
here compiles, passes its own AST tests, and accepts no contract syntax at
all.
