## Rationale
P3400 subsumes P4451: under `-fcontracts-p3400` the assertion-control
specifier `< std::contracts::controls::enforced >` is an ordinary label,
whose allowed set is the terminating semantics, so every program P4451
accepts means the same.  P4451's tests carry a RUN line for each of
`-fcontracts-p4451` alone, `-fcontracts-p3400` alone and both; this commit
adds the last two to each (and `-fcontracts-p3850` to the feature-test
macro test), expecting the same results, or P3400's own diagnostics where
P3400 reads the specifier differently -- the lookup cases, where its
`contract_control` using-directive finds an unqualified `enforced`.  Their
expectations under the `p3400` prefix are already in the files, inert
until now.  It also adds the two cases of the option-off test whose
specifier does not name `enforced` and is therefore diagnosed as a P3400
label.  P4451R3's `defaulted` tests get the same, `defaulted` then being
P3400's empty label (so `defaulted | review` behaves as `review`).
They cover the lookup rule, redeclarations, the modules cases, the
feature-test macros (`-fcontracts-p3400` implying `-fcontracts-p4451`),
constant evaluation and initialization, run time under a configured
quick_enforce, ignore and observe and under dynamic selection, streaming
through a BMI, and P3097 virtual calls with a P3595 configuration.

## Compile gap
None.  Pure test additions.  They need P3400's labels with their
allowed-semantics facet, P3595's configurations, the umbrella option and
P3097's virtual calls.
